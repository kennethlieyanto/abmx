## How it works

`abmx` never guesses. Mail that is not labelled is not fetched, a parser that is
not strict does not import, and a row the bank reported as failed never reaches
the ledger. Broken labels are named and retried after you fix the parser or the
Gmail rule.

<CardGrid>
  <Card title="Route with labels" icon="list-format">
    gmailctl applies exactly one `receipt/<parser-id>` label to transaction mail.
    The label is the contract; there is no sender list to drift.
  </Card>
  <Card title="Parse with runtime data" icon="document">
    A parser is a `config.toml` plus fixtures under `~/.config/abmx/parsers/`.
    No compiler, no rebuild, no bank code in the binary.
  </Card>
  <Card title="Import, or report broken" icon="approve-check">
    Strict rows are written to Actual Budget through the official Node client.
    Anything unsure becomes an actionable broken label instead of a guess.
  </Card>
</CardGrid>

## Why not parse statements?

Statements are complete and bank-authoritative, but they are a month late. The
point of abmx is to see a transaction the day it happens.

|                        | Email notification                        | Monthly statement         |
| ---------------------- | ----------------------------------------- | ------------------------- |
| Latency                | minutes                                   | ~30 days                  |
| Granularity            | one event per message                     | whole period              |
| Completeness           | lossy (thresholds, spam, missing channels) | bank-authoritative        |
| Metadata               | merchant, channel, reference id           | often less                |
| Parsing cost           | stable HTML labels                        | PDF/CSV/Excel, fragile    |

Statement import is planned, not implemented. Until then, abmx imports live
transactions and leaves reconciliation against the statement to you.

## Install

<Tabs>
  <TabItem label="Nix">
    ```bash
    nix run github:kennethlieyanto/abmx -- --version
    ```

    The flake bundles the Actual helper and Node.
  </TabItem>
  <TabItem label="Cargo">
    ```bash
    cargo install --path crates/abmx
    ```

    From a clone. The Actual sink additionally needs Node 22+ and the helper's
    `node_modules`; see [Install](/start/install/).
  </TabItem>
  <TabItem label="Container">
    ```bash
    docker build -t abmx .
    docker run --rm abmx --version
    ```

    The image contains the binary and the Node helper.
  </TabItem>
</Tabs>

## Honest about maturity

One fetcher (Gmail), one real sink (Actual Budget), one reference sink (JSONL).
The primitives are stable; the integrations are thin. abmx ships no bank
parsers — they are authored at runtime and belong to you.
